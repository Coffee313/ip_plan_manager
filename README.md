# IP Plan Manager v18

Веб-приложение для совместного ведения IP-планов с импортом и экспортом Excel.

## Изменения v18

- для работы обязательны регистрация и вход по корпоративному логину и паролю;
- при регистрации пользователь указывает реальное имя для журнала изменений;
- в личном кабинете отображаются только собственные и полученные проекты;
- владелец создаёт ссылку-приглашение и передаёт коллеге четырёхзначный PIN отдельно;
- после принятия приглашения проект постоянно появляется в списке проектов пользователя;
- владелец назначает сокращённый или полный доступ;
- сокращённый доступ соответствует прежним правам коллеги: работа с IP-планом и экспорт;
- полный доступ дополнительно разрешает переименование, импорт Excel и резервные копии, но не удаление проекта и не управление участниками;
- пароли и PIN хранятся как scrypt-хеши, токены сеансов и приглашений — как SHA-256-хеши.

## Изменения v17

- при первом открытии пользователь указывает имя; профиль и постоянный токен сохраняются в текущем браузере;
- имя можно изменить кнопкой пользователя в верхней панели;
- создание, изменение и удаление строк IP-плана, импорт и изменения проекта записываются в общий журнал с именем автора и временем;
- журнал открывается боковой панелью, не закрывает IP-план и позволяет перейти к связанной строке;
- удалить проект может только создавший его пользователь;
- проекты старых версий без PIN открываются с PIN `1111`;
- первый зарегистрированный пользователь, успешно открывший старый проект, становится его владельцем;
- профили пользователей, права владельцев и журналы включены в резервные копии.

## Изменения v16

- каждый проект защищен отдельным четырехзначным PIN;
- после первого успешного ввода браузер получает постоянный токен доступа и повторно PIN не запрашивает;
- PIN хранится только как scrypt-хеш, постоянные токены также хранятся только в виде SHA-256-хешей;
- старый проект без PIN остается закрытым, пока администратор не задаст PIN на сервере;
- список проектов виден внутри корпоративной сети, но чтение, изменение, экспорт, переименование и удаление требуют токен проекта;
- импорт сначала полностью проверяет Excel и не заменяет последний исправный исходник при ошибке;
- IPv6 явно отклоняется: текущая модель данных поддерживает только IPv4;
- поврежденный `workspace.json` теперь дает явную ошибку вместо отображения пустого проекта;
- бэкап содержит проверяемый manifest и не считается успешным, если проект не удалось включить;
- восстановление проверяет весь архив до замены данных и переключает каталог проектов атомарным переименованием;
- внешний каталог копий можно задать через `IP_PLAN_BACKUP_COPY_DIR`;
- построение дерева подсетей оптимизировано с O(N²) до зависимости от глубины IPv4-префикса;
- добавлены интеграционные тесты для Python 3.11/3.12;
- systemd units усилены sandbox-настройками, добавлен HTTPS-пример Nginx.

### Доступ к проектам

При создании проекта задайте четыре цифры. Чтобы поделиться проектом, владелец открывает пункт `Доступ и приглашение`, создаёт ссылку и передаёт её коллеге. PIN следует передать отдельно. После принятия приглашения проект сохраняется в личном списке коллеги.

Проекты не отображаются посторонним зарегистрированным пользователям. PIN дополняет секретную ссылку-приглашение, но не заменяет сетевой firewall и HTTPS.

Для проекта старой версии без сохраненного PIN автоматически действует PIN `1111`. После первого успешного открытия он записывается как scrypt-хеш. Рекомендуется затем заменить известный PIN непосредственно на сервере:

```bash
cd /opt/ip-plan-manager
./.venv/bin/python set_project_pin.py PROJECT_ID
```

Скрипт запросит новый PIN дважды, не показывая его на экране. Этой же командой можно сбросить PIN существующего проекта; все ранее выданные токены проекта будут отозваны.

### Пользователи и журнал

Регистрация требует реальное имя, уникальный корпоративный логин и пароль длиной не менее 10 символов. Секретный токен сеанса хранится в `localStorage`, а на сервере сохраняется только его SHA-256-хеш. Пользователям старой версии предлагается дополнить существующий профиль логином и паролем без потери созданных проектов.

Кнопка `Журнал` открывает панель справа. События доступны всем пользователям, имеющим доступ к проекту. Каждое событие является ссылкой на соответствующую площадку, подсеть или хост; для уже удаленной строки интерфейс показывает текущий IP-план и сообщает, что строка удалена.

## Исправления v15.1

- изменения существующей подсети больше не могут случайно захватить соседние подсети при расширении маски, например `/24 -> /23`;
- намеренная суперсеть по-прежнему создается отдельной подсетью через `+ Подсеть`;
- при переносе подсети хосты автоматически наследуют новый сетевой адрес с сохранением host-offset;
- пример: `172.17.10.20` в `172.17.10.0/24` после переноса сети в `172.17.20.0/24` становится `172.17.20.20`;
- перед переносом проверяются network/broadcast, пересечения с более специфичными подсетями, дубликаты IP и вместимость новой маски.

## Что добавлено в v15

- поддержка нескольких независимых проектов;
- создание, открытие, переименование и удаление проектов;
- в каждом проекте хранится собственный IP-план и собственный импортированный Excel;
- совместная работа нескольких пользователей через один сервер;
- изменения других пользователей появляются в интерфейсе примерно в течение 1,5 секунды;
- защита от тихой перезаписи данных при одновременном редактировании через ревизии проекта;
- файловая блокировка проекта между несколькими процессами Gunicorn;
- ежедневные автоматические бэкапы в 00:00 по локальному времени Debian-сервера;
- `Persistent=true` у systemd timer, поэтому пропущенный из-за выключенного сервера бэкап выполняется после следующего запуска;
- хранение резервных копий за последние 30 дней по умолчанию;
- отдельный скрипт ручного бэкапа и восстановления;
- готовый systemd deployment для Debian;
- Gunicorn для многопользовательского серверного режима.

## Совместная работа

Все данные проекта сохраняются на сервере после каждого изменения.

Клиенты проверяют ревизию открытого проекта каждые 1,5 секунды. Если коллега изменил IP-план и локально ничего не редактируется, интерфейс автоматически обновляется.

Если два пользователя начали редактировать одну и ту же старую ревизию, второй запрос не перезапишет данные первого пользователя. Сервер вернет конфликт ревизии, клиент обновит проект, после чего изменение можно повторить.

Это оптимистическая блокировка. Жесткой блокировки строки на время ввода нет.

## Проекты

После запуска приложение показывает список проектов.

Можно:

- создать новый проект с пустым IP-планом;
- открыть существующий проект;
- переименовать проект;
- удалить созданный текущим пользователем проект;
- внутри проекта начать работу с нуля;
- импортировать `.xlsx` или `.xlsm`;
- экспортировать текущий IP-план обратно в Excel.

Каждый проект хранится отдельно:

```text
data/
  users.json
  projects/
    <project-id>/
      project.json
      audit.json
      workspace.json
      source.xlsx / source.xlsm
```

## Debian, рекомендуемая установка

Установите Python и поддержку virtualenv:

```bash
sudo apt update
sudo apt install -y python3 python3-venv
```

Распакуйте приложение в постоянный каталог. Например:

```bash
sudo mkdir -p /opt/ip-plan-manager
sudo chown -R "$USER":"$USER" /opt/ip-plan-manager
```

Скопируйте содержимое папки `IP_Plan_Manager_Web` в `/opt/ip-plan-manager`, затем:

```bash
cd /opt/ip-plan-manager
./deploy/install_debian.sh
```

Скрипт:

- создаст `.venv`;
- установит Flask, openpyxl, filelock и Gunicorn;
- создаст `ip-plan-manager.service`;
- создаст `ip-plan-manager-backup.service`;
- создаст `ip-plan-manager-backup.timer`;
- запустит приложение;
- включит ежедневный бэкап в 00:00.

По умолчанию приложение доступно на:

```text
http://SERVER_IP:5080
```

systemctl list-timers ip-plan-manager-backup.timer

## Автоматические бэкапы

Бэкапы создаются каждый день в 00:00 по локальному времени сервера.

Каталог:

```text
data/backups/
```

Формат имени:

```text
ipplan-backup-YYYYMMDD-HHMMSS.zip
```

В ZIP входят все проекты, их `workspace.json`, метаданные проекта и исходные Excel-файлы.

По умолчанию удаляются бэкапы старше 30 дней как из локального каталога, так и из `IP_PLAN_BACKUP_COPY_DIR`. Срок можно изменить через переменную:

```text
IP_PLAN_BACKUP_KEEP_DAYS
```

В systemd unit по умолчанию установлено:

```text
IP_PLAN_BACKUP_KEEP_DAYS=30
```

Для хранения всех резервных копий можно задать `0`.

### Ручной бэкап

```bash
cd /opt/ip-plan-manager
./.venv/bin/python backup.py
```

### Восстановление

Перед восстановлением остановите приложение:

```bash
sudo systemctl stop ip-plan-manager
```

Затем:

```bash
cd /opt/ip-plan-manager
./.venv/bin/python restore_backup.py data/backups/ipplan-backup-YYYYMMDD-HHMMSS.zip
```

Скрипт попросит ввести `RESTORE`.

После восстановления:

```bash
sudo systemctl start ip-plan-manager
```

## Многопроцессная работа

В Debian deployment используется:

```text
Gunicorn
2 workers
4 threads на worker
gthread
```

Все операции записи в конкретный проект выполняются под файловой блокировкой. Поэтому несколько процессов Gunicorn и несколько пользователей могут безопасно работать с одним хранилищем на локальной файловой системе Debian.

Для каталога `data` рекомендуется использовать локальный ext4/xfs. Для NFS/SMB потребуется отдельно проверить семантику файловых блокировок.

## Безопасность доступа

Каждый проект защищен PIN и постоянным токеном браузера. Приложение по-прежнему предназначено только для доверенной корпоративной сети: четырехзначный PIN имеет небольшое пространство вариантов и не заменяет firewall, VPN или корпоративную авторизацию.

Рекомендуется:

- не публиковать TCP/5080 напрямую;
- ограничить сервер корпоративной сетью через firewall;
- поставить Nginx перед приложением и использовать сертификат внутреннего PKI;
- при необходимости добавить корпоративную авторизацию/SSO на reverse proxy.

Пример Nginx находится в:

```text
deploy/nginx.conf.example
```

Debian installer по умолчанию привязывает Gunicorn к `127.0.0.1:5080`. Для осознанного прямого доступа можно перед установкой задать `IP_PLAN_BIND=0.0.0.0:5080`.

## Ручной серверный запуск без systemd

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
./start_server.sh
```

По умолчанию `start_server.sh` слушает:

```text
0.0.0.0:5080
```

Можно изменить:

```bash
IP_PLAN_BIND=127.0.0.1:5080 ./start_server.sh
```

## Локальный запуск

Для одиночного локального использования по-прежнему можно использовать:

```bash
./start.sh
```

На Windows:

```text
start.bat
```

Локальный Flask-запуск предназначен для тестов и одиночной работы. Для общего сервера используйте Gunicorn/systemd.

## Основной функционал IP-плана

- создание площадок с корневым CIDR;
- редактирование площадок;
- создание вложенных подсетей;
- автоматическая CIDR-вложенность;
- проверка пересечений;
- автоматическая синхронизация CIDR и Gateway;
- создание и редактирование IP хостов/интерфейсов;
- числовая сортировка хостов по IPv4;
- карточка хоста по кнопке `i`;
- CPU, RAM, HDD/SSD, тип оборудования, статус, роль, подсистема и Comment;
- поиск;
- сворачивание дерева;
- импорт `.xlsx`/`.xlsm`;
- экспорт Excel;
- минимум 3 host/interface строки под каждой подсетью;
- светло-серые host-строки;
- Excel Outline по CIDR-вложенности;
- экспорт только полезных колонок A:Q;
- столбцы после Q скрываются.

## Маски и ввод IP

В интерфейсе фиксируется только гарантированно неизменяемая часть адреса на уровне полных октетов.

Примеры:

- `/8` → `10.`
- `/16` → `172.17.`
- `/20` → `172.17.`
- `/24` → `172.17.1.`
- `/28` → `172.17.1.`
- `/30` → `172.17.1.`
- `/31` → `172.17.1.`
- `/32` → весь адрес фиксирован

Backend всегда проверяет фактическую принадлежность введенного адреса CIDR.
